## Separate Subtask correction

Installed Office Start, capabilities and dependency write guard already honor explicit arrays (including empty arrays) and retain legacy sequencing only for NULL. Installed `eflow_r7.complete_subitem(uuid,jsonb)` additionally imposes an unconditional earlier-sibling condition. That condition must be limited to `s.dependency_ids IS NULL`.

The apparent Office inconsistency in `eflow_r7.command` is not an additional required change: its progress/submit/review branch first rejects `v_kind<>'personal'` with **Use the existing Office evidence workflow**. Its remaining sibling check preserves the Personal contract and is left untouched. The completion-proposal decision path calls the same `eflow_r7.complete_subitem`, so one guarded predicate change fixes both ordinary direct completion and accepted Subtask Lead completion without changing review permissions, scheduling, evidence, finances, receipts or status machinery.

Mobile's temporary deployed-backend sibling override must also be removed for explicit dependencies; backend-first rollout is required. Missing Office dependency fields must remain unavailable, and cancelled selected prerequisites remain unresolved. No arbitrary new capability, version flag, nested feature or fallback writer is needed.
